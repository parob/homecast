# Play Store release scripts

Direct Google Play Developer API integration. No fastlane, no gradle plugins,
just the REST API with a service-account JSON key.

## One-time setup

Already done for Homecast — the service account is
**`play-publisher@homecast-483609.iam.gserviceaccount.com`**, `androidpublisher.googleapis.com`
is enabled, and it is linked in Play Console. On a new machine you only need a key:

```bash
gcloud iam service-accounts keys create ~/.config/play/homecast-play-publisher.json \
  --iam-account play-publisher@homecast-483609.iam.gserviceaccount.com \
  --project homecast-483609
chmod 600 ~/.config/play/homecast-play-publisher.json
export PLAY_JSON_KEY=~/.config/play/homecast-play-publisher.json
```

A key's private material is shown **only at creation** — an existing key listed by
`gcloud iam service-accounts keys list` cannot be recovered, so minting a new one is the
normal move. Delete keys you no longer use; they stay valid until deleted.

The GCP half is only half of it: the SA must also be linked in **Play Console → Setup →
API access** with **Release manager** rights. That link lives in the Play Console web UI, so
no amount of `gcloud` access substitutes for it. Prove the whole chain works before building
anything — create an edit and read the tracks back (see *Check what is live*).

From scratch: create the SA, link it in Play Console, then
`gcloud services enable androidpublisher.googleapis.com --project=homecast-483609`.

## Check what is live — before every release

The version code must exceed every code already on **any** track, and the local files lie:
`src-tauri/gen/android/tauri.properties` is **not** regenerated by a normal build. It sat at
`1000001` (1.0.1) while production was really serving `1001001`. Ask Play:

```bash
scripts/play/.venv/bin/python - <<'EOF'
import os, requests
from google.oauth2 import service_account
from google.auth.transport.requests import Request
c = service_account.Credentials.from_service_account_file(
    os.path.expanduser(os.environ['PLAY_JSON_KEY']),
    scopes=['https://www.googleapis.com/auth/androidpublisher'])
c.refresh(Request())
H = {'Authorization': f'Bearer {c.token}'}
B = 'https://androidpublisher.googleapis.com/androidpublisher/v3/applications/cloud.homecast.app'
eid = requests.post(f'{B}/edits', headers=H, json={}).json()['id']
for t in requests.get(f'{B}/edits/{eid}/tracks', headers=H).json().get('tracks', []):
    for r in t.get('releases', []):
        print(t['track'], r.get('status'), r.get('versionCodes'))
requests.delete(f'{B}/edits/{eid}', headers=H)
EOF
```

Then bump **all three** to match — they are not derived from one another:
`src-tauri/tauri.conf.json`, `package.json`, and `gen/android/tauri.properties`
(`versionCode = major*1000000 + minor*1000 + patch`, so 1.1.2 → `1001002`).

Note `requirements.txt` pins `google-auth` + `requests` only — these scripts use the REST API
directly, so `googleapiclient` is **not** available.

## Build + upload to Internal track

```bash
cd app-android-windows-linux
export PLAY_JSON_KEY=~/.config/play/homecast-play-publisher.json
PLAY_NOTES="What's new in this release" npm run play:release
```

To target a different track: `PLAY_TRACK=beta npm run play:release`.

## Promote between tracks

```bash
PLAY_JSON_KEY=~/.config/play/homecast-play-publisher.json \
PLAY_VERSION_CODE=1001001 \
PLAY_FROM=internal PLAY_TO=production \
PLAY_NOTES="What's new" \
npm run play:promote
```

If the app is still in **Draft state** (initial launch hasn't been approved yet),
add `PLAY_DRAFT=1` — releases will be staged as `draft` until the app exits draft.

Staged rollout: add `PLAY_FRACTION=0.2` for 20%.

## Push store listing metadata + images

```bash
$VENV/bin/python scripts/play/listing.py \
  --json-key $PLAY_JSON_KEY \
  --package cloud.homecast.app
```

Listing copy lives inside `listing.py`. Images come from:
- icon-512 + feature-1024x500: `/tmp/play-assets/`
- screenshots: `app-ios-macos/screenshots/` (first 8 PNGs alphabetically)

## What you still have to do in the Play Console web UI

The Publisher API does NOT cover these — must be done manually:

- Content rating (IARC questionnaire)
- Data safety form
- Target audience & content (age, ads disclosure)
- App access (reviewer credentials for sign-in flows)
- Pre-launch testing requirement (12+ testers / 14 days for first-time launchers)
- Submit-for-review flow
